## الإذن والنطاق الأصلي — قبل إلغاء شرط النسخ

السجل: `logs/upload-authorization-20261124-191158.json`.

هذا قبول لنطاق البورد والكاميرا وقاعدة ESP32-CAM-MB المعزولة فقط. العزل
**إقرار من المستخدم**، وليس صورة فحص مستقلة أو قياسًا كهربائيًا. لم يُعتمد
توصيل الريلاي/IR/OLED السابق، ولا يُسمح بحمل mains أو إعادة توصيل هذه الوحدات
قبل مراجعتها. `HARDWARE_REVIEWED=false` وENABLE_* للأجهزة الخارجية الأربعة
تظل false؛ لا فتح اقتران أو تعديل مالك أو تعلم/إرسال IR في هذه الدفعة.

## بوابات التنفيذ الأصلية — تاريخية، شرط النسخ أُلغي لاحقًا

1. **usb-review:** تأكيد نطاق USB المعزول من المستخدم، مراجعة المصدر المعطّل،
   و`-CheckOnly` للأدوات وCOM13. الفحص الأخير exit 0؛ لا يقرأ هوية الشيب.
2. **chip-backup:** بناء جديد من المصدر دون حذف الكاشات، قراءة MAC المتوقع
   `f0:24:f9:10:80:a4` ورفض أي اختلاف، ثم backup كامل 4,194,304 بايت وبصمته.
3. **upload-guarded:** إدخال FLASH المفوّض، إعادة فحص MAC والمصدر وبصمات ملفات
   البناء، ثم رفع مع تحقق. لا `SkipBackup` ولا `AllowEnabledOutputs` ولا retry.
4. **usb-smoke:** بعد نجاح الرفع والنسخ فقط، قراءة محدودة من COM13 عند 921600.
   لا أوامر للتطبيق ولا حفظ للصور. يلزم ثلاث رسائل status من هوية متطابقة
   بإقلاع ثابت وuptime متزايد، وثلاث JPEG ذات CRC سليم تُفك إلى VGA 640×480،
   وإبلاغ الأجهزة الخارجية بأنها معطلة، ثم إغلاق المنفذ.

الـhelper له مهل أصلية محدودة وتنظيف لأبنائه المملوكين؛ الغلاف له مهلة 1500
ثانية. timeout أو فشل كتابة/تحقق نتيجة غير مكتملة أو مجهولة، لا تصريح إعادة
محاولة تلقائية. لا إغلاق أو قتل للـviewer القديم أو عمليات أخرى لحجز المنفذ.

### تحديث المستخدم: كارت microSD ‏4GB

أبلغ المستخدم تركيب كارت 4GB؛ لم تُفحص سعته أو محتوياته، ولم يحدد إن كان
موجودًا وقت محاولة الاتصال الفاشلة أم رُكّب بعدها. لا يُستنتج أنه سبب الخطأ.
الكارت منفصل عن الفلاش الداخلي **4MB** الذي يُطلب backup له. المصدر الحالي
يستخدم `Preferences`/NVS للإعدادات و`LittleFS` لبيانات IR، ولا يهيئ واجهة SD.
لا طلب أو إذن لفرمتة الكارت أو قراءة ملفاته أو الكتابة عليه أو إضافة دعم SD.

الخطوة المقترحة لتبسيط تشخيص الاتصال: يفصل المستخدم USB أولًا، ويزيل الكارت
مؤقتًا، ثم يعيد USB فقط مع بقاء المكونات الخارجية مفصولة. أبلغ المستخدم وجود
زري **RST وFLASH**. الخطوة المقترحة: إبقاء RST مضغوطًا، ثم ضغط FLASH معه،
تحرير RST مع إبقاء FLASH مضغوطًا؛ في الفحص القادم المقترح يبقى FLASH مضغوطًا
خلال الاتصال بدل تحريره بعد ثانية، ولا يُضغط RST ثانية أثناء ذلك.
